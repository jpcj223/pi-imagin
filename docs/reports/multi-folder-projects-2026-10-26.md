## 结论

主要实现已落地：用户只关联文件夹、不配置默认目录；已有会话同步关联清单，单任务可以跨目录操作。主会话关键场景已通过真实模型对话，桌面／手机界面及仅凭项目 ID 创建会话的接口已验证。

**不能宣布全部验收通过。**真实模型“继续同一个子代理”仍会漏传 `resume`，另建会话或由父会话代做；后台按同一 ID 恢复并使用最新范围的能力已通过 SDK 集成测试。这两类结果必须区分。Qwen 在歧义修复后的追加复测遇到模型服务 HTTP 402（余额不足），未能完成；该批不计通过。

## 最终行为

- 项目保存不要求 `defaultPath`；编辑弹窗移除默认按钮和会话目录选择。关联名、复制路径、排序和目录管理保留。应用默认工作区及零文件夹项目工作区保留。
- `defaultFolderId` 作为旧数据的内部启动／资源定位字段保留；重排不改变它，也不让它代表任务操作目标。已有会话的 SDK cwd、历史存储位置和资源配置范围不随目录清单刷新而改变。
- 会话保存项目 ID；每轮模型请求及工具调用读取最新项目定义。运行期间变化通过仅供模型的上下文副本告知，不往历史里伪造用户消息，也不要求刷新、新建或重启会话。
- 新增目录可以在同一会话使用，改名立即影响后续定位，解除关联不再沿用旧关联范围。解除最后一项时，有会话的项目会准备其独立工作区，原会话继续使用。
- 文件工具要求标准绝对路径；项目命令明确指定 cwd，实际路径和命令 cwd 返回可核实信息。普通模型 Bash／PowerShell 调用不能隐式回退。跨目录复制复用既有按字节复制工具。
- 用户直接 `! / !!` 在多根且缺少 cwd 时明确拒绝，并提示通过普通对话说明目标或从目标目录打开终端；单根可确定位置。交互终端保留自己的目录，不自动跟随 Agent 切换。
- 失效根单独报告；工具只校验本次涉及的根，不让一个无关失效目录阻断其他目录，也不重建被移走的根。
- 项目子代理继承项目身份；创建、续接及重开读取最新清单。命令／复制工具仍受角色原有权限限制。多目录工作树隔离需要明确目标仓库，非隔离任务不得用 cwd 切换子会话目录。
- 不修改已安装 SDK、不修改全局 `process.cwd()`，不自动加载附加根的 `.pi`，不改变插件、技能、子代理配置、MCP 的全局／项目范围。

整个项目被移除时的历史会话兼容行为沿用原规则，不按同路径的新项目转移身份；本轮没有顺带重做该产品行为。历史记录可保留原关联数据，但不冻结仍存在项目的当前执行范围。
