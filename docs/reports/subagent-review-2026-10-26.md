## 结论与边界

此前三个会话的失败属于相近的工具使用问题：漏传 `resume`、普通任务误传 `cwd`，或向已完成子代理发送 `steer_subagent`。不能仅凭文件存在或助手声称“已续接”判定通过，必须对照实际工具参数和子会话 ID。

本次没有发现“有效 resume 被底层静默转换为新建”的证据。现有恢复入口保留原 ID，恢复失败也不会自动调用新建。此次仅澄清有歧义的工具说明并补充实际操作标记；不能据此宣称所有模型都不会再漏传参数。

- `lib/subagent-extension.ts`：`Agent` 依据 `resume` 分派到现有 `runtime.resume` 或 `runtime.start`；恢复调用不接受 `model`、`input_files`、`isolation`、`cwd` 等新建选项。工具入口与参数名称保持不变。
- `lib/subagent-runtime.ts`：恢复会校验子任务存在、父会话归属及运行状态；读取或重开原子会话后，在同一会话提交新任务。未修改这条路径。
- 应用运行时 `get_tools` 中确实包含可见的 `resume`；使用已安装 SDK 的 OpenAI Completions 转换路径，在 HTTP 发送前截获声明，`resume` 仍存在，没有发生序列化丢失。该截获不发送网络请求。
