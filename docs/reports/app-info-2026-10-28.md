# 应用能力与插件查询优化

## 提交与范围

先按用户要求将上一版探索限制、报告分页和验收记录提交为 `84d4b0f`（`perf(agent): 限制快速探索与长报告回传开销`）。未推送。本报告对应随后继续实施的改动，尚未提交。

本轮新增只读工具 `pi_imagin_info`，没有继续增加通用行为提示词或改写模型回复。目标是给模型一个准确、低成本的信息来源，减少为普通能力／插件问题翻应用源码、扫描本地配置的需要；不能保证模型永远选择最短路径或自然措辞。

## 代码及注释位置

- `lib/app-info-extension.ts`：实现与主要中文注释。`capabilities` 每次调用从 SDK 注册表读取，区分工具注册、声明与暴露方式；隐藏工具不返回。界面入口与本轮权限分开描述，只返回模型标识和工具名，不返回配置、凭据、参数或本机路径。工具名列表最多 80 个，超过时明确标注截断。
- 同一文件的 `search_plugins`：复用插件页的 `searchPluginCatalog`，沿用固定来源、缓存、超时和失败行为；每次最多十条、每条描述最多 500 字符，返回来源、命中总数、已返回数、当前页剩余数及下一段位置。
- 同一文件的 `plugin_details`：复用插件页 `loadPluginDetail` 和包名校验；返回有限公开元数据与最多 6000 字符的纯文本 README，保留来源和部分失败。明确未安装、未执行、未验证兼容性。网络错误、取消不能变成“目录中没有”。
- `lib/rpc-manager.ts`：仅普通工具会话加载该扩展；仅聊天、子代理不因此增加工具或提示词。只读预设允许查询，不因此获得写入或 Shell 权限。注释说明加载边界。
- `lib/app-info-extension.test.mjs`：实际 SDK 工具调用、切换预设后的状态、隐藏工具、只读行为、分页缓存、来源限制、非法包名、详情摘录、部分失败及取消。
- `lib/app-info-scope.integration.test.mjs`：实际 RPC 的普通只读／仅聊天隔离。
- `docs/agents/tools.md`：记录入口及边界。

扩展工厂随会话初始化／重载加载。新会话直接使用，已运行的旧包装器需按原有重载流程加载新工具。未改会话格式、资源范围、项目信任或安装入口。

## 真实应用验收

实际应用 30143，通过应用 API 创建并持久化两条会话，消息及工具记录保留在应用；只用指定两个模型、思考级别 off。每个模型两轮，未要求模型调用特定工具名，也未限制回复格式。耗时是提交到空闲状态的近似时间，包含轮询误差，不能解释为纯推理时间。

## 结果及未覆盖

代码已提供实时能力信息和现成目录／详情查询，两个模型都主动使用；本轮安装问题没有重现直接进入角色扮演，也没有为普通插件问题进行大规模源码调查。

仍未解决：过长回复、查到部分资料就扩大结论、把应用功能与底层或特定插件实现混淆。返回字段能明确证据范围，无法从代码上保证模型遵守；本轮不以关键词硬路由或不断扩张提示词掩盖这些问题。

公开包详情的实际网络加载、部分失败和摘录由受控网络响应及现有模块测试覆盖；付费对话没有找到需要进一步读取详情的 Pi 候选，因此没有在真实对话中调用 `plugin_details`。真实安装、插件兼容性、子代理实际执行、长时间稳定性不属于本轮验证，未算作通过。
