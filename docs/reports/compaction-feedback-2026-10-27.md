# 压缩无操作提示修复

## 原因与改动

SDK 在没有可摘要的旧消息时返回 `Nothing to compact (session too small)`，已有压缩且没有可再次摘要的消息时返回 `Already compacted`。这两种结果此前被直接显示成红色英文错误。

仅对这两个明确结果分类并提供中、英、繁体中文提示，使用主题中性色，保留关闭按钮；真实错误继续显示红色原始诊断。压缩按钮、`/compact` 及空回复的恢复入口使用相同分类。没有修改 SDK、压缩阈值、模型提示词或历史格式。

## 验证

- 实际应用 `127.0.0.1:30143`，会话“你是什么”，ID `01a17c59-bc4e-703c-9a28-6a1ade530cac`：点击压缩按钮显示“当前会话内容较少，暂不需要压缩。”；关闭后消失。
- 同一空闲短会话执行内置 `/compact`：显示相同中性提示，输入框清空，没有新增用户／助手消息。本次未触发摘要模型请求。
- 页面计算样式：文字 `rgb(119, 129, 140)`，背景 `rgba(0, 0, 0, 0.03)`，提示使用 `status`。
- 相关定向测试 11 项通过：包括精确分类、多语言渲染、两个命令入口和真实失败路径。类型检查及改动文件 lint 通过，`git diff --check` 通过。
- 初次组件测试共 82 项，81 项通过；既有模型选择器测试期待 `No models`，当前基线已由 `emptyLabel` 显示 `Select model`，该无关断言未修改。已通过的相关测试未重复运行。
- `Already compacted` 使用受控回调及组件测试验证，未人为创建需要付费摘要的会话。

## 补修：提示前红框闪动

用户反馈出现中文提示前仍闪红框。确认 SDK 手动压缩失败时，先通过 `compaction_end` 事件发出 `Compaction failed: Nothing to compact (session too small)`，HTTP 随后返回无前缀原文。首次修复只识别后者，最终页面截图漏掉了中间事件。

补齐两个确定的带前缀无操作消息，实时事件和 HTTP 响应均直接采用中性提示。其他前缀、网络失败等仍保持错误。新增消息分类及组件渲染覆盖这两个阶段，定向测试 3 项通过，改动文件 lint 通过。实际短会话压缩按钮复测显示中性中文提示，截图为 `output/live-acceptance-2026-10-27/compaction-flash-fixed.png`。未修改 SDK，未发起付费模型对话，未提交或推送。

## 补修：压缩按钮自身闪动

按钮原有独立的运行中样式：立即切为红色背景与文字，10px 停止图标替换 11px 压缩图标，文字由“压缩”变为“正在压缩…”，造成短请求变色和宽度跳动。

按钮改为主题中性色，两种图标统一 11px；两种标签通过同一网格共同占位。复用既有 `useDeferredLoading`，请求持续 200ms 后才显示运行中文字和停止图标；请求、运行锁、停止点击及可访问名称仍立即生效。

按钮组件定向回归测试通过；现有延时提示的受控计时测试通过（快速结束不显示、慢请求在 200ms 显示、完成清除、卸载取消），类型检查及改动文件 lint 通过。实际短会话点击前后宽度均为 80.0625px，提示正常；鼠标悬停后的颜色使用主题正文色，无红色运行样式。截图为 `output/live-acceptance-2026-10-27/compaction-button-stable.png`。运行中的颜色及占位由组件测试验证，实际页面只核对了点击前后尺寸，未声称逐帧录屏验收。没有发起付费摘要或模型对话，未提交推送。

## 补修：重复点击时提示和滚动条跳动

压缩按钮、斜杠命令和实时开始事件均会先清空 `compactError`，结束后再添加同样提示，导致输入区域高度先缩小再恢复。现在开始时保留已有中性提示，真实错误仍清除；成功、取消或新结果到达时正常替换。未加入固定空白区域。

受控请求测试覆盖两个入口各连续三次及实时开始／结束事件，断言过程中从未清空中性提示，成功和取消正常清除；相关 2 项回归通过，类型检查及 lint 通过。实际应用同一短会话连续点击三次，四次测量一致：提示 y=728.1667px、高=33.3333px；消息区高=579px、scrollHeight=1212px、scrollTop=632.6667px。截图 `output/live-acceptance-2026-10-27/compaction-repeat-stable.png`。未发起付费模型对话，未提交推送。
