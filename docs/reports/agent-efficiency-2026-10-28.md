# 对话效率与表达优化记录

## 实施范围

本轮针对安装意图误判、普通比较过度调研及机械表达，保留 SDK、权限、用户配置和历史格式，不提交或推送。

- `lib/subagents.ts`：内置 `explore` 默认 8 轮后进入既有收尾流程，可继续原子会话；普通执行及自定义角色不强制套用。不是 8 次工具调用、超时或费用硬上限。
- `lib/subagent-extension.ts`：子代理报告每页最多 8000 个 UTF-16 代码单元，长结果明确标注节选及下一页 offset；原报告保留，支持继续读取。前台、后台和失败部分输出共用此逻辑，保留真实 ID、失败状态及清理告警。
- `lib/conversation-guidance.ts`：在已有普通会话输出约定中增加两条短指导，要求先回应当前问题、意图歧义时低成本查证或澄清、普通比较避免默认文档普查。工具说明补充限定委派问题和交付范围。未增加“蓝色大肥鱼”专用规则，没有修改用户 AGENTS.md 或 SDK 基础人设；仅聊天和精确提示词的原有入口继续保留。
- 四个相关测试文件补充运行限制、同会话续接、报告分页、Emoji 边界、失败与后台通知、指导注入验证。开发约定同步至 `docs/agents/subagents.md`。

## 结论与限制

这两次普通比较没有重现此前约 3 分 30 秒、子代理 52 次调用及超长报告的路径。本次提示、上下文和思考设置不保证与旧对话完全相同，因此不能用作严格提速百分比或长期稳定性结论。

8 轮收尾、同会话续接与 8000 字符分页由真实 SDK 加模拟服务商的定向测试验证；付费对话未强行触发轮数上限或制造长报告。六轮未发生服务商错误或人为超时中止，工具记录未见安装与配置写入。

**未解决项**：识别陌生对象后主动查证仍因模型而异；“安装”歧义虽然未直接触发扮演，仍可能优先给角色卡方案；机械表达、绝对化比较和缺少引用没有稳定改善。现阶段不据此增加一套关键词路由、全局工具次数硬限制或不断扩张提示词，也不宣称“更像人”已验收通过。后续如继续，应优先用已有记录定位事实来源和应用能力信息缺口，再做小范围调整。
