# 应用内 Pi 输入法定位修复

## 复现与判断

在真实 Windows PTY、xterm 和 Pi regular 模式下加载私有合成历史，不请求模型。
输入 `hello` 后，Pi 显示的编辑光标距终端左侧约 39px，而输入法 textarea 和组合文字的锚点在 1131px，复现截图中的行末偏移。

SDK 的 regular 渲染器本来会把终端光标移到编辑位置，但默认隐藏真实光标。测试中仅启用 SDK 已有的 `PI_HARDWARE_CURSOR=1`，锚点即恢复到 39px；据此判断为 ConPTY 对隐藏光标位置更新的传递问题，并非候选框自身需要页面偏移补偿。

## 修复范围

仅应用专属 terminal-bin 的 Pi 启动入口默认设置该变量，CMD 使用 setlocal，Git Bash 使用进程环境；外部注册入口、系统环境、Pi 设置及 SDK 均不修改。已有变量和 Pi 的显式光标设置继续优先。
已经运行的 Pi 需要退出重启，或新建终端再运行；收起展开不重启进程。

## 验证

- 命令入口及性能相关 4 项测试通过，包含默认启用、已有值保留、外部入口、参数覆盖和退出码。
- 真实 Pi 浏览器检查 6 个场景通过：英文、中文与 emoji、文字中间移动光标、自动换行、窗口缩放、全屏还原。输入锚点与显示光标偏差小于 2px。
- Chromium 组合输入流程确认未选定文字不发送，确认后的中文和 emoji 正常显示。
- 代码检查和差异空白检查通过；仅清理本次创建的测试 PTY。
- 浏览器产物：`output/playwright/terminal-ime-fixed/results.json` 和对应场景截图；修复前对比在 `output/playwright/terminal-ime/geometry.json`。

## 验证边界

浏览器自动化验证的是输入法锚点和组合输入，不包含 Windows 系统候选窗的原生截图；系统候选窗最终显示仍需实际输入确认。用户若显式关闭真实光标，继续尊重其设置。
