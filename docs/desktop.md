# Windows 桌面版

桌面版使用独立窗口，自动启动和回收本机服务。安装包内置 Node.js、npm、网页生产资源与服务端依赖，无需用户另外安装 Node.js 或通过浏览器运行。

## 使用

安装 `Pi-Imagin-Setup-0.1.0-x64.exe`，之后双击桌面或开始菜单的 **Pi Imagin**。重复打开会回到已有窗口，不启动第二个工作区。

点击窗口关闭按钮后，应用留在系统托盘，当前页面、输入和本地服务继续保留。点击托盘图标、托盘菜单的“打开 Pi Imagin”或再次双击快捷方式即可恢复。需要完全结束时，选择托盘菜单的“退出 Pi Imagin”或应用菜单“文件 → 退出”；此时才清理会话、终端和服务。托盘创建失败时，关闭窗口仍会正常退出，避免隐藏后无法找回。

首次打开默认浅色、简体中文。左侧新建会话直接使用默认工作区；添加项目可选择本机文件夹。模型、技能、插件、子代理和 MCP 在窗口内设置中管理。完整历史保留在独立的应用窗口中，外部文档链接交由系统默认应用打开。

工作区采用一体化浅色标题栏，保留 Windows 窗口控制按钮。左侧项目导航、中间对话、右侧文件或会话目录并排显示，终端在下方收起；具体布局见 [主页工作区](workspace-layout.md)。

## 数据与退出

- 现有 pi 配置和会话仍位于用户的 `.pi/agent`，默认工作区继续使用 `pi-cwd` 日期目录，兼容 `PI_CODING_AGENT_DIR`。
- 桌面窗口偏好、端口和启动记录位于 `%APPDATA%/Pi Imagin`，与安装目录分开。
- Node 编译缓存位于同一目录的 `node-compile-cache`，减少再次启动时的解析开销；清除该缓存不影响会话和配置。
- 升级或卸载桌面程序不删除项目目录、会话、模型配置或桌面偏好。
- 本地服务仅监听回环地址，每次启动使用内存中的随机认证信息，窗口请求自动携带；认证信息不写入启动记录。
- 文件夹选择仍须通过已有目录校验和允许根授权，原生窗口不会绕过文件访问边界。
- Git 与项目语言工具沿用本机环境；使用工作树或 Git 来源插件时，需要本机已有 Git。

启动失败时，窗口显示错误和重新启动入口。启动记录是 `%APPDATA%/Pi Imagin/desktop.log`，只用于本机排查。记录超过 2 MiB 时轮换。

启动记录分别标记进程、启动窗口、服务连接、认证及初始恢复就绪的耗时，并记录目录列表、偏好、目录校验、正文读取和 SDK 加载阶段。记录仅包含阶段、状态码和耗时，不记录会话 ID、文件路径、消息或凭据。桌面启动请求使用有超时限制的回环直连，内置页面不经过代理自动发现；模型和 MCP 的服务端代理配置保持原有行为。

桌面首屏先完成轻量认证与侧栏读取，所选会话正文按需加载同一 SDK，初始恢复后再预热其余入口。偏好、目录摘要和已有运行状态共用轻量读取模块，不初始化智能体；正文仍使用 SDK SessionManager，缓存、写入和文件授权规则保持一致。网页端保持原预加载时机。独立启动视图覆盖页面导航，等待初始选择、目录校验及正文定位恢复完成（或显示明确错误），再以 160 毫秒淡出；不会先露出欢迎页再恢复原会话。恢复等待有 90 秒上限，超时显示错误与重试入口。系统启用减少动态效果时直接结束动画，动画不设最低展示时长，淡出回执异常时最多等待 280 毫秒释放覆盖层。关闭到后台不会被启动完成自动唤起。

## 开发和打包

在 `desktop` 目录运行 `npm ci` 安装桌面构建工具。复用正在运行的开发服务测试独立窗口：

```bash
npm run desktop:dev
```

先停止同目录开发服务，再在项目根目录执行：

```bash
npm run desktop:pack
```

构建脚本从 Node.js 官方下载 Windows x64 运行时，验证官方 SHA-256 校验表，生成 Next.js standalone 服务，并补齐动态 SDK 依赖和原生终端资源。补齐依赖之前保存同一次构建的框架运行文件清单，供最终打包时裁剪框架编译和开发资源。安装包输出到 `dist-desktop`；`build`、依赖和安装包都不提交。

安装优先减少解压写入：NSIS 使用 ZIP 直接解压至安装目录，并关闭当前未使用的差分安装包格式，避免默认 7z 流程先解压到临时目录再复制。原 `appId`、用户安装模式、目录选择和卸载时保留用户数据的策略不变。ZIP 包会比原 LZMA 包稍大，此处选择安装速度优先。

`afterPack` 调用 `desktop/package-resources.cjs`，按以下边界整理安装资源：

- `next` 与 `@next` 采用同次 standalone 构建的运行清单，保留全部许可证；构建标识、必要入口和每个保留文件的 SHA-256 必须匹配，否则停止打包。其他依赖不按框架清单裁剪，SDK 的动态导入、扩展文档、类型声明、图片模块及 npm 保留。
- x64 终端保留所需 NODE、DLL 和 EXE，排除其他平台的预编译文件与原生调试 PDB；许可证保留。
- Electron 原生语言资源保留英语、简体和繁体中文，与当前界面支持范围一致；浏览器引擎、渲染和图形资源不裁剪。
- 依赖中附带原文件的 JS、TS、CSS 调试映射不进入安装包。

整理只作用于仓库内完整的桌面构建产物，不跟随资源链接。复用现有生产资源重新打包时，必须有与其构建标识一致的 `server/.desktop-framework-manifest.json`，先执行 `node desktop/package-resources.cjs dist-desktop/win-unpacked`，再生成安装器，无需重复执行网页构建。缺少清单时使用正常生产打包流程生成，不从其他构建借用清单。源依赖及 `build/desktop-server` 中的调试映射保留，便于开发排查。

本地生产资源准备完成后，`npm run desktop:start` 可直接打开桌面窗口。运行时使用单独内置 Node 运行服务，不把 node-pty 切换到 Electron 的原生模块 ABI。
