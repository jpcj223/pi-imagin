# Windows 桌面版

桌面版使用独立窗口，自动启动和回收本机服务。安装包内置 Node.js、npm、网页生产资源与服务端依赖，无需用户另外安装 Node.js 或通过浏览器运行。

## 使用

安装 `Pi-Imagin-Setup-0.1.0-x64.exe`，之后双击桌面或开始菜单的 **Pi Imagin**。重复打开会回到已有窗口，不启动第二个工作区。关闭窗口会等待会话清理，再回收本地服务和子进程。

首次打开默认浅色、简体中文。左侧新建会话直接使用默认工作区；添加项目可选择本机文件夹。模型、技能、插件、子代理和 MCP 在窗口内设置中管理。完整历史保留在独立的应用窗口中，外部文档链接交由系统默认应用打开。

工作区采用一体化浅色标题栏，保留 Windows 窗口控制按钮。左侧项目导航、中间对话、右侧文件或会话目录并排显示，终端在下方收起；具体布局见 [主页工作区](workspace-layout.md)。

## 数据与退出

- 现有 pi 配置和会话仍位于用户的 `.pi/agent`，默认工作区继续使用 `pi-cwd` 日期目录，兼容 `PI_CODING_AGENT_DIR`。
- 桌面窗口偏好、端口和启动记录位于 `%APPDATA%/Pi Imagin`，与安装目录分开。
- 升级或卸载桌面程序不删除项目目录、会话、模型配置或桌面偏好。
- 本地服务仅监听回环地址，每次启动使用内存中的随机认证信息，窗口请求自动携带；认证信息不写入启动记录。
- 文件夹选择仍须通过已有目录校验和允许根授权，原生窗口不会绕过文件访问边界。
- Git 与项目语言工具沿用本机环境；使用工作树或 Git 来源插件时，需要本机已有 Git。

启动失败时，窗口显示错误和重新启动入口。启动记录是 `%APPDATA%/Pi Imagin/desktop.log`，只用于本机排查。记录超过 2 MiB 时轮换。

## 开发和打包

在 `desktop` 目录运行 `npm ci` 安装桌面构建工具。复用正在运行的开发服务测试独立窗口：

```bash
npm run desktop:dev
```

先停止同目录开发服务，再在项目根目录执行：

```bash
npm run desktop:pack
```

构建脚本从 Node.js 官方下载 Windows x64 运行时，验证官方 SHA-256 校验表，生成 Next.js standalone 服务，并补齐完整生产依赖和原生终端资源。安装包输出到 `dist-desktop`；`build`、依赖和安装包都不提交。

本地生产资源准备完成后，`npm run desktop:start` 可直接打开桌面窗口。运行时使用单独内置 Node 运行服务，不把 node-pty 切换到 Electron 的原生模块 ABI。

## 验证记录

2026 年 10 月 14 日生成并更新本机 Windows x64 安装版。安装目录中的应用归档、生产构建标识、Next.js、终端依赖和 Node 运行时与新包一致；桌面及开始菜单快捷方式存在。

- 从实际安装目录启动，窗口直接进入工作区；缺少窗口认证的服务请求被拒绝，重复启动复用已有实例。
- 验证文件重命名、回收和恢复，以及内置 Windows 终端的真实命令输出。
- 在独立临时目录使用已授权的硅基流动模型发送一条短测试提示词；真实回复、会话保存、名称修改和完整历史导出通过，测试会话随后清理。
- 正常退出后本地服务已回收，再次启动继续使用相同工作区来源。
- 桌面运行时 4 项、会话关闭及终端生命周期 40 项测试全部通过；布局验证另见 [主页工作区](workspace-layout.md)。

原生目录选择和外部链接已接入，但尚未人工点击检查原生选择窗口、外部应用及完整卸载流程。页面截图来自同一工作区的网页界面验证。安装包当前没有代码签名证书；完整 MCP 集成测试的未完成情况记录在布局说明中。

## 技术依据

窗口隔离与 IPC 来源校验参考 [Electron 官方说明](https://www.electronjs.org/docs/latest/tutorial/security)，目录选择参考 [dialog API](https://www.electronjs.org/docs/latest/api/dialog)。安装范围、快捷方式和数据保留参考 [NSIS 配置](https://www.electron.build/nsis/)。
