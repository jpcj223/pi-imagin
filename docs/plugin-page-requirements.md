## 一、用户已明确的需求

### 1. 页面整体结构

- 插件入口位于最左侧主导航栏。
- 主体采用左窄右宽的两栏布局，以用户双矩形示意图为参考，避免重复嵌套设置分类栏。
- 左侧固定展示已安装插件及其筛选、管理入口，右侧承担目录搜索、卡片和独立详情。
- 布局和样式一起优化，整体清楚、舒适、比例协调、信息层级合理。
- 允许在参考图基础上作合理改进，具体尺寸、间距与交互由设计把控，并与当前系统兼容、不产生冲突。

### 2. 页面顶部简化

- 去掉“返回工作区”按钮。
- 去掉“插件”标题后面的目录路径。
- 顶部用途介绍改成简短描述，减少当前大段说明。

### 3. 最左侧图标导航区

- 图标组距离窗口上方稍远一些，增加顶部留白。
- 主页、搜索、插件等图标之间的纵向间距适当加大。
- 支持拖动调整导航入口顺序。
- 这一要求针对最左侧图标导航，不应误做成仅对已安装插件列表排序。

### 4. 插件侧栏与目录

- 按最新反馈，移除“已安装／搜索安装”切换按钮，左侧始终只展示已安装插件。
- 右侧默认展示可安装目录，提供独立搜索，不受左侧是否已安装插件影响。
- 左右搜索互不覆盖；已安装项和目录卡片均可进入详情。
- 搜索框稍微突出一些，改善当前颜色过浅、不易辨认的问题；保持系统风格一致。
- 去掉侧栏底部“添加插件”按钮。
- 微调侧栏间距、层次与布局，使整体舒适、排列合理。

### 5. 主内容区与安装流程

- 去掉当前手动安装表单，包括来源输入框和对应的 npm、Git、本地路径示例展示。
- 增加可安装插件的搜索能力；不能仅用已安装列表的本地筛选代替。
- 插件以卡片方式展示，包含 Logo、插件名称和描述。
- 用户找到插件后，通过“安装”按钮安装，不再先进入“添加插件”表单。
- 去掉安装位置 `~/.pi/agent/{npm,git}` 的展示。
- 安装流程方向以最新反馈为准，取代初版“手动填写来源”的页面方案。

### 6. 插件描述展示（以最新删除指令为准）

- 描述及使用说明显示来源原文；应用自身菜单与操作提示继续跟随应用语言。
- 移除翻译提示、原文／译文切换、预置译文、翻译接口、工作进程、专用依赖及资源声明，不再读取翻译偏好和缓存。

## 二、整理后需要避免的理解偏差

1. 两处路径都要去掉：顶部当前目录，以及安装区的 `~/.pi/agent/{npm,git}`；这不代表隐藏所有页面中的所有路径。
2. 两个入口都要调整：移除侧栏“添加插件”按钮，同时撤掉右侧手动安装表单，并接上搜索后的安装操作。
3. 最新要求已经替代此前的模式切换方案：左侧常驻已安装，右侧默认浏览目录。
4. 目录卡片包含 Logo、名称、描述和安装操作；点击主体或名称查看独立详情，安装按钮不触发详情。
5. 用户允许调整细节，核心范围仍是本次导航和插件页面；不因此扩展成模型、技能、MCP 等页面的重新设计。

## 七、滚动加载与首次打开优化（2026-10-23）

用户明确授权修改：用滚动追加替代上一页／下一页，提前加载以减少等待，同时改善第一次进入插件页面的耗时。

- 工作区启动完成后，空闲预热公共目录首页；不读取项目插件、不执行插件，浏览器节流模式跳过预热。首次进入不再额外等待搜索防抖。
- 目录文字和图标分开加载：先呈现名称、描述与安装入口，再独立补齐图标，不等待图标元数据服务。
- 当前批显示后只预取下一批，距离底部约 1200px 时追加；按包名去重，保留当前卡片和滚动位置，不自动抓取全部插件。
- 后续加载失败仅在底部提示并提供重试，不清空列表。更换搜索立即取消旧目录请求，过时结果不得混入当前列表。
- 缓存公共目录和详情，复用正在进行的请求；当前标签页保留一份首页快照，过期先显示再刷新，损坏缓存忽略。缓存有容量上限，图标只处理最近批次，避免滚动越长网络请求越多。
- 卡片短暂停留或名称获得焦点时预热一个详情；点击立即显示已有信息，详细说明随后补齐；返回恢复查询、累计卡片及位置。
- 保留安装范围、信任、启停、更新、卸载、设置草稿、主题与应用语言；不恢复描述翻译，不调整目录搜索匹配或排序规则。
