# MCP 测试与登录

## 单次连接测试

`POST /api/mcp/test` 先校验请求来源、JSON 类型、条目标识、工作目录和项目权限，再读取当前文件中的条目。不能测试浏览器任意提交的配置，也不能把测试当作绕过信任的连接入口。

MCP 全局关闭、引用网页密码、配置损坏或项目不可信时返回明确的类型化拒绝，不启动进程、不联网、不执行配置中的命令。

通过 SDK 内部的连接实现完成一次有时限的测试。`!command` 的计算与连接步骤共用受限队列；超时、Stop 和取消都清理连接及子进程。日志、错误、命令输出、URL 与头字段在返回前脱敏。

结果记录工具数量、连接状态和耗时，不持久保存原始凭据。配置改变后旧状态失效；同内容测试可共享当前状态，不能把一个条目的结果套到另一个条目。

## OAuth 登录流程

`POST /api/mcp/sign-in` 创建或加入登录流程，`GET /api/mcp/sign-in/[flowId]` 查询进度，POST 提交手动重定向地址，DELETE 取消。流程 ID 不携带秘密。

认证 URL 由浏览器打开，不在服务器主机自动弹出窗口。远程访问提供粘贴回调地址的输入方式；匹配完整授权状态和目标，不接受任意 URL 冒充回调。

轮询只读取已有流程，不重新执行认证。关闭设置面板不等于删除有效凭据；用户明确取消才中止流程。短期流程结束后过期并清理。

## 并发与信任变化

测试和登录复用相同的配置读取、验证、命令队列及脱敏逻辑。条目在过程中改变、删除、关闭，或项目信任被撤销时，结束阶段再次检查，不能用旧决定启动新连接。

令牌写入由 SDK 的认证存储和文件锁负责。登录成功可保留合法凭据，但信任被撤销或 MCP 被关闭时不得继续连接。登出按名称和 URL 对应的存储键删除，并阻止较早启动的流程重新写回令牌。

界面保留当前状态、取消和重试操作，区分“等待用户登录”“连接失败”和“权限拒绝”，不把所有情况都显示为笼统错误。

连接成功不等于账号登录成功。没有 OAuth 凭据且未经新授权即可连接的服务显示“无需登录”并隐藏登录按钮；凭据未知、失败、需要授权或已登出时保留登录入口。兼容旧流程字段 `alreadySignedIn`，其提示仅表示未进行新的登录授权，不据此宣称账号已登录。已存储访问令牌的服务显示“重新授权／退出登录”。
