# 0004：以最小模式修改实现模型开关

## 状态与背景

已采用。`enabledModels` 是 SDK `--models` 语义的白名单：通配符、非通配符模糊匹配和可选推理后缀。只列举当前可见模型后整份写回会丢失未登录服务商、用户通配符和推理固定值；全部不匹配时 SDK 又会退回所有模型，因此需要专用的最小修改规则。

## 修改规则

- 从不主动修改未匹配模式；凭据缺失、目录更新和跨机器使用都可能暂时导致不匹配。
- 关闭模型只展开覆盖该模型的模式，保留顺序和推理后缀；只匹配该模型的条目可删除。
- 开启模型追加明确的 `provider/modelId`。
- 完全开启的多模型服务商可折叠为经验证的通配符，保留第一次出现位置。带后缀、被更宽模式覆盖或仅有一个明确引用时不折叠。
- 首次修改无限制范围时按服务商生成通配符，后续新增模型仍可自动启用。
- 验证 `provider/*` 和 `provider/**` 的真实匹配集合；`*` 不跨 `/`，不能假定覆盖嵌套 ID。
- 仅在不丢失失配模式或推理后缀时删除已无必要的范围键。
- `prune` 才清理失配条目，普通开关不顺带修复其他内容。
- 保存模型配置后的 `resync` 先迁移模型引用，再迁移服务商，重新验证通配符并保留此前完整启用的服务商。编辑器按数组移动跟踪改名，不能从差异猜测新增和删除。
- 保留顺序，因为它影响模型轮换和新会话的初始模型。

## 接口与界面

拒绝关闭最后一个模型，返回 `409 { reason: "last-model" }`，避免“关闭全部”反而启用全部。

浏览器发送模型、服务商或清空等意图，不拼接模式；SDK 是语义的唯一来源。内置和扩展服务商逐模型控制，`models.json` 服务商整体控制。部分开启时整体开关为关闭，再点击完成全开。

禁用原因和缺失服务商的说明必须显示为可见文字，使用 `aria-describedby`；不能只放在触屏无法触发的悬浮提示中。设置路径和范围数量由服务端返回。

## 兼容与并发

全局设置使用 SDK 文件锁，只合并对应字段，不能覆盖其他并发设置。项目 `enabledModels` 完整覆盖全局，API 此时只读并显示原因。客户端对修改排队。

TUI 和网页相互读取模式；TUI 自己整份保存仍可能展开通配符。运行中的会话保留创建时范围，新会话和选择器通过缓存失效取得新值。网页保留推理后缀，但不自动创建固定推理条目。
