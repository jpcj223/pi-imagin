# 0006：以插件式流程管理 MCP 与 Code mode

## 状态

当前已实现内置扩展加载、会话 MCP 主机、设置管理、测试、OAuth 登录、项目覆盖和服务器添加。早期逐服务器项目信任方案已由 CLI 一致的目录信任替代。

## 设计背景

网页服务在一个进程中运行许多会话，不能直接沿用 CLI 的每会话启动全部 MCP、无限连接等待、继承宿主秘密和在服务器本机打开浏览器的行为。浏览历史不应启动服务器，Stop 必须能取消连接等待，配置变更应在后续运行中生效。

## 加载与兼容

普通会话使用 SDK 导出的 Code mode、工具搜索和 MCP 工厂，注册为同名、可替换的内置扩展。遵守内置禁用、项目覆盖、`noExtensions` 和第三方替换。仅聊天不加载扩展。

子智能体可选择 `codemode: inherit | on | off` 和 `mcp: on | off`，缺省关闭。启用时保留配置工具边界，使用自己的 MCP 主机及项目信任；只读工具配置仍阻止未声明只读的 MCP 调用。

## MCP 主机

内置 MCP 工厂读取空服务器列表，等待时间为 0。包装器在实际运行前重新读取文件及信任，只注册变化的条目。直接声明的工具执行可中止等待，按需工具在搜索或脚本调用时连接。

普通浏览、切换、自动命名和 Fork 不连接 MCP。连接操作串行，注销覆盖尚未完成连接的窗口；迟到传输被拒绝，避免脱离管理的子进程。默认空闲 10 分钟后注销，可由 `PI_WEB_MCP_IDLE_MS` 调整。

传输观察真实连接、工具列表、认证需要和错误，设置状态由内容 HMAC 关联，不能保存原始秘密。第三方扩展先注册的同名服务保留并显示冲突，网页不显示 TUI 的 MCP 管理器。

## 设置管理

面板无需活动会话，未选择项目时仅列全局文件。只读 GET 不创建认证文件、不执行命令、不连接网络，也不触发沙箱自检。

服务器按作用域分组，提供启用、暴露、删除/恢复、测试、登录和添加。`hidden`、`codemode`、`direct` 对请求开销和可见工具有不同含义；旧 `codemode-deferred` 兼容显示为 `codemode`。

项目覆盖只包含全局服务器的启用及暴露字段，不能包含连接地址或命令。写入采用 SDK 编辑器、文件锁和原子替换，保留未知字段、注释与其他条目。

## 导入与秘密

用户粘贴 URL、命令或客户端配置，浏览器发送原文，服务端重新解析并校验。导入器不执行程序或链接。缺失值以普通或密码字段补齐；字面秘密仅保存到全局，项目使用明确环境引用。

HTTP 头或 OAuth 秘密若引用宿主环境变量，显示变量名并获得确认，不能暴露值。不得引用网页登录密钥 `PI_WEB_PASSWORD`，stdio 子进程也删除该变量。

仅对没有风险资源且没有已有信任决定的新目录，支持在同一步明确授予目录信任并保存。写入失败回滚新决定；过宽信任、祖先拒绝和已有项目资源不能被快捷入口绕过。

## 测试、登录与停止

测试和 OAuth 共用配置校验、命令队列、连接时限及脱敏。浏览器打开认证地址，远程访问可粘贴回调。取消、超时、删除、配置变更和信任撤销必须及时结束连接；较早流程不能在登出后重新写回令牌。

任务停止时，不可将未送达的提示词算作模型运行，也不能发完成通知。Code mode 需要 SDK 沙箱自检成功，失败时明确说明可用性，不替换成不受限执行环境。
